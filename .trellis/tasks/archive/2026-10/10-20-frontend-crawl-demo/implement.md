# JobInsight 功能首版 · 实施与验收计划

## 0. 交接限制与开始条件

本文件由规划 agent 编写。本轮仅交付文档，未实现产品功能、安装依赖、启动 Docker 或采集数据。

接手实现者先读 handoff.md、prd.md、design.md 及已配置上下文。当前状态应为 planning；只有用户在看到最终摘要之后明确要求按本版方案实施，才可运行 task.py start。不要把之前“可以创建任务/认可方向”的许可当成本版最终实施批准。

本任务作为一个集成的前端功能交付实施。爬虫暂缓，不创建一个隐含必做的采集子任务。若拆多个实现者，下列阶段是依赖顺序；任何代理不得重写他人的改动。

## 2. 用户状态、纯逻辑与查询契约

负责范围：新增前端用户状态和小型工具；不修改后端招聘 DTO。

- [ ] 实现 version=1 的本地状态读取、校验、写入和错误降级。
- [ ] savedJobIds 唯一且保留收藏顺序，操作使用 JobItem.id。
- [ ] knownSkills 保留 null 与 [] 的区别，读写不夹带岗位正文或 API 响应。
- [ ] compareJobIds 独立、唯一、最多 3 个，不作为收藏副作用。
- [ ] 实现 query 解析/序列化，覆盖 false 字符串、空值、非法数字、重复标量、分页/排序白名单。
- [ ] 实现技能交集/差集派生，输出未设置/无标签/可核对三种有依据的结果，不输出评分。
- [ ] 写关键逻辑测试，先验证契约再把控件接入。

建议测试：
1. 收藏重复、添加/取消、重新创建状态后恢复、别名规范化责任边界。
2. 坏 JSON、未知版本、错误字段类型、存储读取/写入异常均不崩溃；不调用 clear()。
3. 技能未设置与明确空数组不同；岗位无标签不输出缺口；重复标签只计一次。
4. has_skills=false 正确，非法查询不传给 API；min>max 阻止提交；查询 round-trip 等价。
5. 对比第 4 项被拒绝，重复项不计数，移除收藏不改变对比。

阶段出口：底层契约通过测试，store 无 API 假数据；后续页面统一复用。

## 7. 验证命令与证据要求

### 7.1 自动检查

在 frontend 目录运行：

~~~powershell
npm run build
npm run test:unit -- --run
~~~

test:unit 是本次若采用 Vitest 时应新增的脚本，当前 package.json 尚不存在；不得直接把未创建脚本当作已验证。若接手时已有等效测试入口，记录实际命令即可。

在仓库根运行：

~~~powershell
.\backend\.venv\Scripts\python.exe -m pytest backend/tests/test_api.py -q
.\backend\.venv\Scripts\python.exe -m ruff check backend/
~~~

如果后端虚拟环境不在该路径，使用项目实际 Python 环境，记录差异。无后端改动时遇到存量 lint 失败，应注明文件和基线，不盲目修改全仓或假装已通过。

### 7.2 MongoDB 与真实运行

先启动 Docker Desktop，再在根目录：

~~~powershell
docker compose up -d
.\backend\.venv\Scripts\python.exe -m pytest backend/tests/test_mongo_aggregation.py -q
~~~

注意：聚合测试连接不可用时会 skip；任何 skip 都不能标为 MongoDB 集成通过。若连接成功但集合为空，先检查本机数据库状态。

现有 backend/app/db/seed.py 会 delete_many({}) 后重新导入整个集合。不要无条件执行 seed 或删除数据卷；只有确认是可重建的基准库、确实需要初始化且用户已授权该重置时，才执行现有导入。已有数据不可当作空库处理。单纯文档交接不需要运行任何写库操作。

服务启动示例（分开终端，勿在规划阶段执行）：

~~~powershell
.\backend\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --port 8000
~~~

前端目录另开终端：

~~~powershell
npm run dev
~~~

### 7.3 浏览器完整任务

使用实际 API 返回的岗位，不硬编码某个以后可能变化的 ID。

1. 从工作台选择实际存在的类别/省份，进入岗位探索并核对控件、URL、结果。
2. 加入三个真实候选，开详情验证收藏状态；刷新确认恢复。
3. 选两个岗位进入对比，加入第三个，再尝试第四个，验证限制。
4. 使用实际有标签岗位，设置一个已有标签，核对交集/差集；明确清空个人技能再核对；另选无标签岗位检查未知状态。
5. 复制对比地址到新的页面/浏览器上下文，验证岗位恢复、个人技能不随 URL 传播。
6. 通过受控请求拦截/测试桩模拟 404、5xx、慢响应乱序和不可写存储；这些是测试输入，不能写入产品数据。
7. 在三种宽度走通核心按钮，打开来源链接。
8. 检查三个分析页真实响应和统计契约，确认没有因局部清单或个人技能改变分母。
9. 记录 MongoDB 模式与本地回退模式分别验证了哪些行为。
