## 0. 输入可用性与交付边界

三份历史来源位于本仓库父目录的 `清洗后数据/`，来源缓存位于父目录的 `原始数据/social_cached.csv`。本次研究时它们在当前机器可见，但都不属于本仓库；本文用来源说明替代跨仓库相对链接，不能保证其他机器存在同名目录。

系统以 MongoDB 7.0 集合 `job_insight.jobs` 作为核心主存储与聚合引擎；后端正常运行直接直连 MongoDB 支撑所有 API 查询与分位数统计，不再在开机时预载本地 JSON 进内存。数据准备流水线 [pipeline.py](../temp/data_prep/pipeline.py) 支持直接灌库 MongoDB 并自动创建 4 组复合索引；离线备份文件 `data/processed/jobs_cleaned_grouped.json` 与复核文件 `data/processed/job_category_review.csv` 严格降权为离线快照归档用途。全新克隆时可通过 `docker compose up -d` 启动数据库，并运行流水线或使用 [seed.py](../backend/app/db/seed.py) 完成数据入库与索引挂载。

## 3. 最小验收场景

| 场景 | 预期结果 |
| --- | --- |
| 21 字段完整映射；`experience_min_years`、`recruitment_headcount` 未作主指标 | 原值仍可追溯，保留字段不被删除或按零填充。 |
| 空薪资、空城市、无技能；人数文本 `5.0` | 标量为空时为 `null`，技能为 `[]`，人数为 5；不限和零不与缺失混用。 |
| 两行原始 19 列相同、ID/链接不同、技能不同 | 合成一组、代表 ID 取字典序最小、保存所有 ID；技能并集，每项保留不同来源依据对。 |
| 两行仅数值文本 `5`/`5.0` 或省级别名不同 | 原始键不同，不能因为后续归一化合成一组。 |
| 规则/独立提案相同但 pending；两路不一致且 pending | 前者可采用规则但不称已确认；后者最终类别为空。AI提案不会自动 confirmed。 |
| 同组一条 confirmed、另一条仍 pending 冲突或确认不同类 | 全组未分类；完成受影响成员的显式一致裁定后重算，不能只改代表记录。 |
| 岗位组内两次相同技能且有不同 `(origin,evidence)` | 岗位/薪资计一次；技能频次计一次，两对依据保留且不串配。 |
| 薪资上限缺失、原文倒置、只有 4 个有效组 | 前两者不算中点；4 组不入排名。恰好 5 个有效组才符合排名样本门槛。 |
| 中点为 10000、20000、30000、40000 | 中位数为 25000，样本数为 4，仍不入排名；代表值清楚标注为区间估算。 |
| G 共 10 组、4 组有技能、其中 3 组有 Python | Python 全量标注比例 K/N=30%，已标注内部比例 K/L=75%，覆盖率 L/N=40%；75% 不得称整体需求率。 |
| G 为空；G 非空但全部无标签 | 前者比例为 `null` 且展示暂无匹配；后者覆盖为 0%、列表为空并说明暂无标签。 |
| 带类别/地区/技能筛选的跨页查询 | 先得到完整组级 G，再计算总数与图表、稳定排序分页；翻页不改变同范围图表。 |

上表是后续变更/验收时仍适用的场景，不是本轮应用测试通过记录。每次输入或处理规则变更后，应重算来源数、组数、技能覆盖、分类覆盖、薪资有效组数与排除数，并复测三份来源 SHA-256。薪资有效样本少于 5 时必须预警且不入排名；技能双分母和覆盖率不能省略。文档维护检查活动链接、CSV 示例和状态一致性；本次纯文档整理不引入测试框架或应用依赖。
