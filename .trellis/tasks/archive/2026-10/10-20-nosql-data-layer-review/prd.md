# 招聘系统 NoSQL 数据层选型与架构复评

## 1. 本次目标

保留招聘主题和已经实现的应用功能，独立评估 NoSQL 应当承担的数据层职责、相对优势与代价，形成其他 agent 可接续的研究、架构候选和验证计划。

本次交付是评估文档，不是数据库改造。评价允许得出“当前样本上优势有限或未证实”，不能预设 MongoDB 必胜。

## 2. 已确认约束

- C1：招聘领域保留；工作台、选岗、候选清单、对比、技能核对和分析功能保留。不得为证明数据库有用而重做前端或更换题目。
- C2：必须使用 NoSQL 是项目约束；MongoDB 是候选选型，仍需解释与实际数据访问模式的匹配。
- C3：MySQL 是有竞争力的对照，比较须覆盖关系模型与 JSON 模型，不能假定其不支持嵌套、数组、索引或聚合。
- C4：现有采集、清洗、灌库脚本按弃用处理。本次不运行、不复用、不恢复跟踪或删除它们；其路径只可作为历史信息。Trellis 自身的任务管理命令不属于此业务脚本弃用范围。
- C5：已有数据可作为只读样本，必须检查本机可用性、哈希和适用范围；脚本弃用不等于自动废弃已有数据，也不证明这些数据仍为实时招聘。
- C6：本轮只编写文档，代码由其他 agent 负责；不安装数据库或依赖、不启动 Docker、不采集、不写数据库、不执行基准测试实现、不改产品代码。
- C7：本轮任务创建和规划已获用户许可；最终架构与任何实现仍需在本版文档审阅后另行批准。

## 3. 背景事实

本机样本为 2,251 个岗位组、一个来源域名、一种顶层字段结构，每个代表 ID 仅有一份当前记录。技能和来源依据嵌套于岗位中。没有已验证的历史版本数据或当前多来源业务查询。

后端已实现 MongoDB 查询与部分聚合，连接失败时可自动回退到本地 JSON；部分分位数仍在 Python 计算。候选和个人技能当前保存在浏览器，不能据此声称 MongoDB 已承担个人工作空间持久化。

data/processed 下的 JSON/CSV 和旧 seed.py 已被 Git 忽略。新克隆环境不保证具备它们。研究输入与代码依据见 research/evidence.md、research/input-audit.json。

## 5. 范围与非目标

本次包含：本机只读审计、官方资料核实、负载与模型比较、数据层候选方案、验证计划、Trellis 上下文和交接文档。

本次不包含：
- 改招聘题目、增删现有用户功能、把收藏迁到服务端、登录/账号/同步功能。
- 恢复旧爬虫/清洗/灌库脚本，或立即重新编写它们。
- 新采集源、真实长期版本或大规模数据的承诺。
- 直接更换生产集合/默认运行模式、驱动升级、部署和写入现有数据库。
- 引入图数据库、搜索引擎或缓存来增加“技术含量”。
- 用重复扩充的数据冒充市场样本或现有业务规模。

## 7. 决策状态

本轮产物应可用于选择下一步验证任务，但不能替代数据库实测。没有阻塞本轮文档交付的产品问题。

当前推荐仅为：保留 MongoDB 作为 NoSQL 的优先验证候选，先验证岗位聚合文档与嵌套查询的建模成本，必要时验证隔离的数据版本发布。固定小样本下尚无已测性能优势。多来源、历史版本和规模增长是条件性扩展，不能用作当前成果。

研究完成与生产改造必须分开；接手者优先按 benchmark-plan.md 做经用户批准的隔离验证，再依据结果更新选型结论。
