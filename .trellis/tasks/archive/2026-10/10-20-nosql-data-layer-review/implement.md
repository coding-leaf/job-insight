本轮只交付文档。用户已许可创建评估任务，未批准新代码、数据库操作或生产迁移。任务维持 planning，不执行 task.py start。

接手者先读 handoff.md。不要沿用旧任务已归档时的“实现已通过”状态，也不要把本版候选设计当成迁移命令。

## 1. 阶段 A：复核输入与本轮结论

- [ ] 读取 prd.md、assessment.md、research/evidence.md、research/sources.md。
- [ ] 确认招聘主题和现有功能保留；个人收藏不迁移；现有业务脚本弃用。
- [ ] git status --short，保留其他 agent 改动。
- [ ] 确认用户是否已在本版摘要后明确批准隔离验证阶段；没有则只展示摘要请求审阅，不再询问已确认的主题。
- [ ] 核对本机输入可用性与审计哈希；缺文件时阻塞依赖它的实验，禁止伪造或重新运行旧脚本。
- [ ] 研究目标版本兼容与驱动状态：MongoDB 7.0、MySQL 8.4、可比客户端。旧 Motor 的生命周期是迁移成本，不是 MongoDB 性能收益。

出口：只有“经批准、可复现、隔离”的验证工作能进入后续阶段；本轮文档到此即可交付。

## 2. 阶段 B：经批准后建立实验，不改产品行为

- [ ] 按 Trellis 创建或细化验证子任务/后续任务，明确边界后再 start；不要对文档父任务直接进行未记录的产品改造。
- [ ] 用独立数据库名与连接配置；连接校验拒绝生产数据库/旧集合。
- [ ] 实现最小的新输入校验及实验导入逻辑，来源为当前已批准投影，不复用 seed.py 或旧清洗/采集。
- [ ] 实现 Mongo 文档、MySQL 关系、MySQL JSON 三种同义数据模型；不引入生产双写或三个长期数据库。
- [ ] 用独立参考逻辑验证 DTO、组计数、技能依据和统计精度。
- [ ] 新代码测试只覆盖有意义的输入/索引/更新/读取边界，不能用实现自己证明自己。

可能影响的路径（仅候选）：
- 实验代码与数据结果放在明确的隔离研究/测试目录，具体目录在新验证任务记录。
- 应用 backend/app/db/repository.py 和 mongodb.py 暂不修改；用适配实验验证，不破坏现有可用功能。
- 后续若使用新的 Python 依赖，固定兼容版本并记录，不能全项目顺手升级。

出口：Q1–Q5 同义正确性通过，环境、输入、查询与原始计划可核对。

## 3. 阶段 C：更新/发布机制与故障验证

- [ ] 按 design.md 的 staging/ready/registry 候选实现最小机制验证，仍只在实验数据库。

- [ ] Q9 明确请求内与跨请求一致性边界；每次读取记录 release_id。
- [ ] 合成故障夹具只用于机制测试，不冒充真实招聘版本历史。
- [ ] 无真实异构来源时 H5 保持未验证；不能为了过关臆造新来源。

出口：失败状态与恢复行为有可审查证据；不能依赖当前普通 Compose 不具备的部署特性。

出口：报告足以支持用户决定后续生产方案，不能以课程约束强行解释负面结果。

## 5. 阶段 E：只有另行批准才做生产改造

这不是本轮授权内容。若报告支持改造，先为选中的最小方案补齐最终需求/设计/实施计划并让用户审阅。不要照抄候选的所有集合和索引。

可能触及：
- backend/app/core/config.py：明确数据后端模式，避免静默回退。
- backend/app/db/mongodb.py、repository.py：驱动、版本解析、统一读取范围和未找到行为。
- 新的受校验导入模块：不得调用已弃用的采集/清洗/灌库脚本。
- backend/app/schemas/：仅在实际新增对外契约时变更，并同步 TS；保持旧 DTO 优先。
- frontend/src/api/client.ts：若需要跨请求版本固定，只修改内部数据协调，不重做页面或迁移个人状态。
- 新的隔离数据库集成测试、README 和真实规格同步。

禁止无条件清库、覆盖旧 jobs、删除数据卷或反向恢复旧业务脚本。
