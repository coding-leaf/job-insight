# 项目现状审查与文档归档设计

## 边界与交付

本任务仅调整文档。产品架构保持为 Vue SPA → Axios → FastAPI → 仓库 → MongoDB 或本地 JSON/Python；个人候选清单和技能状态位于浏览器。报告说明实际架构与限制，不实施数据层改造。

交付两份中文 Markdown 审查文档：项目现状/MongoDB 评估报告与文档时效/归档清单。它们使用英文主题文件名，统一位于 `docs/review/YYYY-MM-DD_HHmmss_<topic>.md`。时间为生成时的 Asia/Shanghai 本地时间，同一批次使用同一个时间戳。结构化只读证据同时保存为该目录下带同一时间戳的 `data-stack-evidence.json`，让活动文档不依赖后续会移动的 Trellis 任务路径。

## 文档布局

```text
docs/                                  当前仍有效的数据契约和状态入口
docs/review/<timestamp>_project-review.md
docs/review/<timestamp>_documentation-audit.md
docs/review/<timestamp>_data-stack-evidence.json
docs/archive/<timestamp>_<original-name>.md
```

文档根目录按用户最新纠正统一为 `docs/`，审查与归档子目录分别采用规范英文 `review`、`archive`。本轮继续使用 Markdown，不引入 Word/二进制文档工具链。当前有效契约保留稳定文件名，新增审查报告和归档快照使用时间戳。

四份 `docs/` 均逐份审查。仍有效的字段、分类、统计约定不因开头状态陈旧而失去权威入口。对部分过时的文件，先将原文件逐字节留档，再刷新原路径：保留有效规则，纠正“尚无实现”等旧状态，区分已完成规则分类、尚未人工确认、数据限制和实现偏差。数据准备清单改为当前输入可用性、已完成产物、仍未解决项及历史来源入口，不能把历史待办全部冒充未完成，也不能把原始依据问题标为已解决。

更新根 README 的报告导航和与证据直接相关的过时环境/输入说明；`PROJECT_HANDOFF.md` 增加历史状态标记及新入口，避免旧交接误充当前成果。不重写历史 Trellis 任务或归档结论，不填充无关的开发规范模板。

## 原文留存与链接兼容

- 归档前保存每份原文 SHA-256；归档后核对一致，四份原文不得因整理丢失。
- 当前 `docs/` 稳定路径保留，因此 Trellis 规范和历史任务对它们的引用继续有效。
- 归档文件采用带时间戳的新文件名，但内容不变。其旧相对链接按原始 `docs/<name>.md` 为基准理解；归档清单逐项提供原路径、快照路径、当前目标和历史来源说明。不要改写快照来伪装原始链接仍按新位置生效。
- 当前文档对仓库外原始 CSV 的旧链接改为明确的历史来源说明或有效入口，只有确实存在的仓库内文件才作为当前可点击输入。不把本机可见、Git 忽略的输入写成新克隆已包含。

## 报告内容与证据

- 七页功能表：路由、真实交互、后端或浏览器承担的职责及能力边界。
- 技术栈：清单声明、前端锁定版本、后端未锁定现状、运行环境与部署配置分别表述。
- Mermaid 架构/数据流图：Mongo 查询与聚合、本地 JSON 回退、Python 分位数、浏览器持久化均明确画出；不画未部署的新系统。
- 数据规模和覆盖来自本任务只读重算及哈希，历史文档仅作交叉证据。
- MongoDB 评估分开回答实际使用、技术必要性和性能证据；公平说明关系库/JSON/SQLite候选，不执行迁移或基准测试。
- 本地代码证据附相对路径和行号，官方文档附直接链接与访问日期；代码/测试存在不等于已经运行通过。

## 风险与恢复

- 主要风险是误删有效契约、归档后链接误读、把旧建议写成已实现、把 NoSQL 项目约束冒充性能结论。通过原文哈希、稳定入口、逐条证据和独立复核约束。
- 不运行旧采集/清洗/seed 脚本，不改变 JSON/CSV，不连接或写入业务数据库。
- 整理可恢复：四份原文完整留档且映射清楚；必要时可用对应快照恢复活动文档。没有数据库回滚操作。

## 执行依据

任务创建和整理范围已确认，规划摘要已呈现。用户已纠正根目录并要求查看实际交付文件；本轮使既定文档交付具体落地，不追加业务代码、数据或服务变更。
