# JobInsight 功能首版 · 技术与交互设计

状态：可供审阅的交接方案。产品范围已认可；本版本最终方案尚未取得实施批准。本轮仅文档。

## 1. 设计原则与事实优先级

1. 复用现有 Vue、Pinia、Router、Element Plus、Axios、useECharts、JobDetailDrawer 和 API，不搭第二套系统。
2. 本次通常无需新增后端接口或 MongoDB 集合。收藏与个人技能是浏览器本地用户状态，不是招聘数据，也不改变分析集合。
3. 现有可执行代码决定当前接口形状；prd.md 决定本次产品目标；design.md 决定新增交互契约；既有数据契约继续决定统计与缺失语义。
4. 规范部分仍是模板，或包含历史描述。frontend/state-management.md 的 setFilter 示例与实际独立 setter 不一致；backend/data-contract.md 的“未来实现”段落也有历史残留。遵守其数据规则，但不得据旧描述重建已有功能。
5. Axios 的当前拦截器校验包装体并返回 AxiosResponse，各 api/*.ts 函数返回 res.data.data。复用这个真实约定，不能把历史设计中“拦截器已直接解包”当事实。
6. 不为本次用户状态另建通用状态机、推荐引擎、存储插件或组件框架。

### 2.1 视觉与布局

沿用 Element Plus 和现有浅色基调：浅灰页面底、白色内容卡、蓝色主操作，薪资用一种强调色，状态有文字说明。统一间距、控件高度和标题层级，以任务操作为视觉重点。避免增加装饰性图表和新的视觉库。

工作台建议布局：

~~~text
[标题：选择适合进一步了解的岗位]        [开始选岗]
[岗位方向] [省份] [岗位学历要求]         [查看岗位]
[我的候选：本地实际数量] [对比：当前实际数量]
[如何使用：筛选 → 保存 → 对比 → 核对来源]
[技能标签设置：选择已掌握标签 / 编辑]
[辅助入口：样本概况 | 薪资分析 | 技能分析]
~~~

工作台的条件选择复用元选项和公共筛选逻辑，点击后导航到 /jobs 并显示已选条件。个人技能选择器按需加载真实标签，不塞入职位列表的筛选状态。候选数与对比数源于用户操作；首版无需为首页增加 API KPI 请求或推荐岗位榜单。

岗位列表保留现有可读表格，新增“收藏”“加入对比”操作。岗位/薪资/地点列优先可见；次要元数据进入详情。窄屏可将次要列折叠或表格内滚动，不能让整个页面持续横溢。

对比使用共享字段行、2–3 个岗位列，表头突出岗位与企业，每列保留详情、收藏、移除和来源入口。不同字段缺失也保留对应单元格。1024 以下允许对比区域横向滚动；390 宽度优先保证单列阅读宽度与明确滚动提示。

统计方法放入简短注释/帮助提示，岗位来源与样本日期仍可查看。不得删除双分母、低样本或未知状态所需的关键说明。

## 4. 持久化与用户状态契约

### 4.1 本地数据

仅写 localStorage 的本应用键 jobinsight:workspace:v1，结构示例：

~~~json
{
  "version": 1,
  "savedJobIds": [],
  "knownSkills": null
}
~~~

这是存储结构说明，不是业务样本。字段语义：

- savedJobIds：代表岗位 ID 的唯一数组，新收藏置于前方；仅从服务端 JobItem.id 产生，不把 source_ids 展开成多份收藏。
- knownSkills：null 表示用户未设置；[] 表示用户明确设置为“暂未掌握这些标签”；非空数组是唯一的技能名，按现有字典大小写/名称精确匹配。不能合并 null 与 []。
- version：固定为 1，运行时校验对象、数组及元素类型。普通 JSON 数据视为不可信形状，不能强制断言为合法状态。

不保存完整岗位正文、薪资快照、API 包装体、用户简历或图表数据。缓存的岗位内容只在内存中存在，详情重新从 API 读取，避免把旧快照伪装成当前查询结果。

读取规则：
1. 无本应用键：空候选、技能未设置。
2. JSON 损坏或已知版本形状错误：本次回退空状态，显示一次可理解的提示；不能白屏，不能执行 localStorage.clear()。首次显式用户修改可重建本应用键。
3. 未知版本：忽略其内容，以会话状态工作，并提示当前无法恢复；不能自动覆写未知格式。
4. 存储 API 抛异常：进入会话模式，用户操作仍生效，提示不能持久保存。
5. 写入失败：内存操作继续，提示刷新后可能丢失；不要伪装已成功永久保存。

不要求多标签页实时协同或跨设备同步；下一次重新打开时读取已保存值。不要安装持久化插件解决这几个字段。

### 4.2 Store 的最小接口

建议暴露 savedJobIds、knownSkills、compareJobIds、canPersist，及 isSaved(id)、toggleSaved(job)、setKnownSkills(value)、addToCompare(job)、removeFromCompare(id)、clearCompare()。

业务约束：
- 收藏/对比添加必须基于加载成功后的规范 JobItem.id。
- 重复收藏/重复对比不产生重复项。
- compareJobIds 仅驻留内存，最多 3 个；从对比 URL 恢复规则见下一节。
- 收藏与对比独立；移除收藏不清空对比，移除对比不取消收藏。
- 同一 store 驱动列表、抽屉、清单和对比条，避免各处独立布尔状态。
- 页面卸载不销毁全局选择；不把用户个人技能放进 useFilterStore。

## 5. 路由与查询语义

### 5.1 岗位探索 URL

公共查询键：category、province、education，education 继续表示岗位要求原标签。

岗位页查询键：keyword、min_salary、max_salary、has_skills、page、page_size、sort_by、sort_order。所有控件初始化与变化都能规范化到 URL，并从 URL 恢复。

- salary：有限非负整数，空输入省略；两边存在且 min_salary > max_salary 时阻止提交并提示，不发错误范围请求。
- has_skills：仅字符串 true / false；不能用 Boolean("false")。
- page：正整数，默认 1；page_size：1–100，默认 20。
- sort_by 只允许 id、published_at、salary_min_monthly、salary_max_monthly、salary_midpoint；默认 id。sort_order 为 asc/desc，默认 asc。
- keyword 去除首尾空白；空值不参与请求。
- 未知/重复的标量查询参数、非法数字和枚举不进入 API，使用默认/未设置值；规范化替换必须避免路由循环。
- 改变公共或局部条件、排序或每页条数时回到第 1 页；清空局部查询不清空公共条件，清空公共条件不擅自清空局部查询。
- 查询空结果显示 0 条及重置入口。页码超过结果末页时，用响应 total_pages 回到末页；若结果为空回到默认页，不能循环请求。

URL 是已应用条件的唯一事实来源；表单可有未提交草稿。保留 useFilterStore 作为公共切片入口，由路由同步；不要同时 watch store、onMounted 和按钮各自调用同一查询而造成重复请求。

具体实现可监听一个规范化请求键并 immediate 加载。按查询代次/取消信号保护响应，旧查询的 finally 不能清除新查询的 loading。更换详情 ID 时同样保护。

### 5.2 对比 URL

形式：/compare?ids=<encoded-representative-id>&ids=<encoded-representative-id>，最多三个。使用 Router 的 query 数组序列化，调用 getJobDetail 时沿用 encodeURIComponent。

- 从对比条进入时，把当前选中项完整写入 ids。
- 带 ids 的 URL 优先于内存对比选择；去重、删除空值并按顺序保留前三个后加载。
- 不带 ids 时使用内存对比选择并规范化 URL；两者都空时显示“先选择至少两个岗位”。
- 获取到别名来源 ID 时，按响应 JobItem.id 归一并去重；仍最多三列，不增加分析记录。
- 移除/添加/替换对比项时同步内存和 URL，刷新与前进后退恢复相同集合。
- 个人技能、收藏状态不写入 URL；别人打开只得到岗位事实，不声称可重现原用户的技能核对。
- 少于两项时仍可显示已选项及“继续添加”入口，但不呈现比较结论。

### 5.3 导航边界

现有 afterEach 会将每次路由 query 同步到 useFilterStore。实施时明确公共条件仅用于四个筛选页面；不要给 /shortlist 或 /compare 盲目附加旧筛选，让用户误以为清单已受筛选。

分析跳转岗位页时清除旧的岗位局部条件和页码，仅携带这次分析中实际支持的条件。技能图表首版仅提供“搜索这个技能标签/关键词”的明确入口，不声称关键词搜索严格等于按技能标签过滤；如需严格标签筛选，必须另立后端契约，不能偷偷改义。

## 6. API 与数据流

| 用途 | 既有请求 | 消费方式 |
| --- | --- | --- |
| 下拉条件 | GET /api/v1/meta/options | 实际可选标签，失败显示重试 |
| 岗位探索 | GET /api/v1/jobs | 全部查询由服务端筛选后分页，不能只筛当前页 |
| 详情/清单/对比 | GET /api/v1/jobs/{id} | 复用 getJobDetail，逐项展示加载结果 |
| 个人技能可选项 | GET /api/v1/stats/skills-top?limit=100（不附筛选） | 取实际返回 skill_name，仅作现有标签选项 |
| 辅助分析 | 既有 overview / stats 接口 | 继续遵循原筛选和统计契约 |

skills-top 的 limit 上限 100 已从后端代码核实；当前字典 24 项可以完整覆盖。若未来返回正好 100 项，不能继续声称是全部技能；提示是当前可用标签，需扩充字典接口时另行设计。接口失败时保留已设置的个人技能，不清空；不得硬编码 24 个标签替代请求。

清单按 savedJobIds 的收藏顺序分页，每页 10 项；只为当前页请求详情，不抓取整个岗位库。对比最多 3 个请求。使用 Promise.allSettled 或等效逐项错误隔离，独立详情失败不清空整批成功结果。重试只重载失败项或当前页。

批量加载复用既有 Axios 实例。批量错误消息可按批次合并一次，但页面每项须区分 404 与网络错误；不能为此改坏全站拦截器，不能引入第二个未受控客户端。若需要小范围 silentError 选项，保持默认单请求提示语义、类型和包装体不变，并补回归检查。

### 6.1 异常状态矩阵

| 场景 | 画面与行为 |
| --- | --- |
| 正在查询 | 骨架或 loading；不把初始值渲染成已确认 0 条 |
| 服务成功但 0 条 | 明确暂无匹配岗位，可修改/清空条件 |
| 服务失败 | 显示加载失败与重试；保留条件；旧结果若保留必须标明尚未更新 |
| 清单/对比单项 404 | 当前数据中未找到，可手动移除；不标记已下架，不删除收藏 |
| 网络错误/5xx | 加载失败，可重试；不能标记岗位不存在 |
| 切换详情 ID | 先清空或遮蔽旧详情，再加载新岗位；迟到响应不能覆盖 |
| 标签为空 | 当前样本暂无技能标签，无法核对 |
| 描述为空 | 来源未提供岗位正文；仍显示其他字段与来源 |
| localStorage 不可用 | 会话模式提示，继续本次操作 |

## 7. 技能核对与比较的精确定义

定义 T 为当前岗位 skills 中去重的 skill_name 集合；U 为用户已选择的标签集合。

- knownSkills 为 null：状态为未设置；展示设置入口，不运行差集断言。
- T 为空：状态为无标注；不输出匹配率或缺口数。
- 已明确设置 U 时：已勾选标签为 T∩U；待核对标签为 T−U。U 为空数组时表示用户明确未勾选任何标签。
- T−U 的标题使用“待核对的岗位标签”，不能称为“必需补齐的能力”。
- 不显示 0–100 适配百分比、总分、录用率或学习优先级。可以显示具体集合及其数量，必须同时说明这只覆盖已有标签。
- 页面编辑的个人技能只改变用户状态；不改变岗位 skills、原始来源依据、图表分母或查询总数。
- 两个岗位的技能差异可列出各自标签；“仅某岗位标注”不能解释为另一岗位不需要。

比较薪资：
- 薪资原文为主；有效中点另标“区间中点（元/月）”。
- 无效/缺边界区间显示原文及无法计算中点，不补 0 或强行计算。
- 不把区间重叠结果写成“达到期望薪资”，不按中点推断实际录用薪资。

来源：优先显示 work_location 原文并辅以已知省/市，缺失城市不能用省填充。来源按钮限 http/https 链接，新窗口打开并防止 opener 关联；其他协议不可作为可点击来源。发布日期仅为发布日期，不冒充采集时间或当前在招状态。
