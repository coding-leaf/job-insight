# JobInsight 岗位选择辅助系统 · 首版需求

## 1. 目标与用户价值

面向需要比较招聘机会的求职学生，提供“设定条件 → 查找岗位 → 保存候选 → 对比岗位 → 核对已标注技能 → 查看来源”的使用流程。用户最终能形成自己的候选岗位清单，并依据可核对的信息作选择。

数据分析服务这一流程。仅有图表、KPI 和表格展示，不满足本任务目标。

## 2. 用户决定与交接边界

- 用户已认可：以“选岗、收藏、对比”为首版核心，技能标签核对作为辅助。
- 已有真实数据；Docker 只是尚未启动，不能将其理解为缺少数据。
- 用户指定：本轮只产出详细文档及 Trellis 交接，具体代码由其他 agent 编写。本轮不得实现产品功能、启动实现 agent 或采集。
- 任务维持 planning。功能方向的认可不等于对本版最终技术方案的实现批准；接手 agent 应先展示本版摘要，取得审阅确认，再按 Trellis 流程进入实施。
- 首轮的“少量爬虫演示”保留为后续事项，不阻塞此首版功能，也不计入本轮前端交付的完成条件。

## 3. 已核实的基础

现有 Vue 3 / TypeScript / Pinia / Element Plus 前端、FastAPI API、MongoDB 仓库和本地真实 JSON 回退可复用。已有岗位查询、详情、总览、薪资与技能统计。

2026-10-20 重算的离线数据覆盖：
- 2,251 个岗位组；岗位名称、企业、学历、来源链接和发布日期均非空。
- 2,194 组具有有效薪资区间；2,016 组有省份；486 组有城市。
- 1,340 组有正文；833 组有技能标签，共 24 种标签；明确经验年限仅 17 组。
- 来源均为 job.ncss.cn，发布日期范围为 2025-10-21 至 2026-10-16。
- 没有经过核实的当前在招状态、实际录用结果、个人能力熟练度或投递记录。

数据覆盖和验证依据见 research/functional-feasibility.md 与 research/data-capability-audit.json。上述数量是审计快照，不是前端展示常量。

## 4. 首版需求

### R1 · 岗位探索

用户可以按岗位类别、省份、岗位学历要求、关键词、薪资区间和技能标注状态查询，查看分页结果、薪资原文、企业、地点及详情。

- “岗位学历要求”是岗位标签的精确筛选，不把它解释成“我的学历可申请哪些岗位”。
- 数值薪资筛选沿用有效区间重叠语义，不承诺筛选后所有岗位都能给出用户期望的薪资。
- 正文、地点、经验或技能缺失时，明确显示未注明或未标注。
- 条件与分页可以通过页面地址恢复；刷新和浏览器前进后退后，控件与结果一致。
- 筛选条件在结果中可见，用户可移除或重置。

### R2 · 候选清单

用户可以在列表和详情中收藏、取消收藏岗位，并在候选清单中继续查看、移除和选择对比。

- 首版本浏览器保存，刷新可恢复；不承诺账号、跨设备或跨浏览器同步。
- 收藏依据稳定岗位标识，重复操作不产生重复记录。
- 已收藏岗位在当前服务中找不到时，保留“当前数据中未找到”提示，用户可主动移除。
- 网络错误或服务不可用不能当作岗位已失效，不能自动删除收藏。
- 保存失败或浏览器不允许持久化时，操作可在本次会话继续，明确提示刷新后可能丢失。

### R3 · 岗位对比

用户可从岗位探索、详情或候选清单中选取 2–3 个岗位并排比较：

- 岗位、企业、地点、薪资原文、有效区间中点、学历要求、经验原文、专业原文、技能标签、发布日期和来源。
- 同一字段的缺失值保持可见，不填补为 0、不限或无需技能。
- 展示事实差异，不生成总适配分、录用概率或所谓最佳岗位。
- 用户可移除、替换对比项；达到上限时提示，不静默替换。
- 对比结果地址可恢复所选岗位；收藏状态和个人技能不包含在分享地址中。
- 对比选择与收藏独立：取消收藏不擅自移除对比项。

### R4 · 技能标签辅助核对

用户可选择自己已掌握的标签，与当前目标岗位的已有标签比较。

- 区分“我已勾选的标签”和“待核对的岗位标签”，列出名称。
- 用户未设置技能时，提示先设置，不能直接把全部岗位标签判为能力缺口。
- 岗位没有标签时，显示“当前样本暂无技能标签，无法核对”，不能显示满分、0 分或无技能要求。
- 结果只说明标签交集和差集，不推断真实能力、熟练度、必需要求或最佳学习路线。
- 个人选择在本浏览器保存，用户可随时调整；不上传简历或个人画像。
- 岗位原始标签和来源信息保留，个人选择不改写招聘数据。

### R5 · 工作台与辅助分析

首页提供“开始选岗”“查看候选清单”“继续对比”等入口，展示真实候选数量及使用说明，让用户能直接开始任务。

保留现有总览、薪资、技能分析页面，作为数据分析入口。图表可跳转到相应的岗位筛选范围；统计中的样本量、技能双分母及缺失说明继续遵循现有契约。

跨页面条件不应造成隐性筛选：候选清单、工作台和岗位对比不受全局分析筛选隐藏；分析和岗位探索页面必须显示自己的当前范围。

### R6 · 可追溯与诚实表达

- 页面使用“招聘样本”“岗位记录”等表述，不保证这些历史记录仍在招聘。
- 来源按钮打开原始招聘链接，由用户核实当前状态，不模拟投递成功。
- 所有业务数值来自 API 或用户实际操作；无服务时显示加载失败，而非伪造结果或 0 条。
- 岗位区间中点不能标为某岗位的“薪资中位数”；中位数仅用于对应样本集合的统计。
- 技术实现术语不占据主界面；详细口径与来源可通过提示和详情查看。

## 5. 首版范围外

- 登录、权限、后台管理、跨设备收藏同步、真实职位发布或投递系统。
- 完整个人资格评估、简历解析、个性化推荐模型、录用概率、个人薪资预测。
- 自动学习路线、技能熟练度判断和根据未标注内容补造能力要求。
- 全国城市排名、经验影响模型、行业扩展和重新清洗当前基准。
- 批量采集、定时采集，以及将新采集样本直接并入正式统计。
- 大范围重构后端、重写组件库或增加新视觉依赖。

## 7. 风险与延后事项

- 部分字段覆盖率限制可支持的解释；辅助核对不等于任职能力判断。
- 首版收藏仅在当前浏览器保留，清除站点存储会丢失，这是明确的交付边界。
- 本地真实 JSON 回退通过测试不代表 MongoDB 集成已通过；实施时须补相应联调。
- 当前任务为一个集成前端功能交付，不再把“爬虫”当作并行必做项。若后续恢复采集交付，创建独立关联任务，明确输出路径和与基准数据的隔离关系。
- 本版无待用户选择的阻塞产品问题；文档采用的实现默认值（单次对比最多 3 个、本地保存、保留学历标签筛选）均在设计和交接中明确，最终技术方案待审阅。
