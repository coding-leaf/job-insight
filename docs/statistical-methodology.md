# JobInsight 统计口径

本文件定义数据使用约定，契约确定于 2026-10-17，状态复核于 2026-10-20。当前已有统计仓库、API 和页面；规范要求与尚未完全满足的实现边界分开记录，见第 5 节。字段与缺失规则见[字段字典](data-dictionary.md)，分类状态见[岗位分类说明](job-classification.md)，数据问题和验证清单见[来源与处理状态](data-preparation-checklist.md)。所有结论限于当前来源样本，不推断整个招聘市场。历史版本见[原文快照](archive/2026-10-20_203614_statistical-methodology.md)。

## 1. 岗位分组与统一查询集合

来源记录数与精确去重后的展示岗位组数分开报告，后文简称“岗位组”。精确分组键为主表中除 `id`、`source_url` 外的全部 19 列，按主表列序取 CSV 解码后的**原始字符串元组**。空单元格仍为 `""`；不先 trim、不转换数字或空值、不规范地区或换行、不忽略发布日期。`5` 与 `5.0`、`广西省` 与 `广西壮族自治区` 因此不会提前合组。CSV 解码可去除文件级 BOM，但不改写单元格内容。

技能关系、技能数组、规则类别、人工/AI提案、最终类别均不参与键。该规则只消除已观察到的内容完全重复，不承诺识别所有语义重复或区分独立招聘。

固定处理顺序：

1. 保留来源表并按原始 19 列分组；代表 `id` 取原值字典序最小 ID，所有成员写入排序后的 `source_ids`。
2. 聚合全组技能关系，按技能名去重并保留不同依据对；规范四个省级别名、转换业务类型。
3. 使用全组成员的离线复核记录计算唯一最终类别。组内冲突时按分类契约保持未分类，不取代表记录的类别。
4. 对最终岗位组施加本次全部筛选，得到集合 G；地区、学历、类别等用投影后的字段，技能条件用组内技能并集。筛选不能先删掉某个来源成员再分组，也不能先按类别筛选再解决分类冲突。
5. 列表总数、图表、比例分母全部基于 G；列表排序稳定后分页，排序同值以代表 `id` 升序确定顺序。聚合不能只使用当前页。

同一筛选范围内，选择某技能后技能比例仍以筛选后的 G 为分母，不擅自去掉该筛选；需要不同分析范围时另行明确，首版不隐式使用另一套集合。技能关联展开只为标签聚合，不增加岗位数、不重复计薪资。

2026-10-17 来源快照有 3000 个来源 ID，2026-10-20 只读复核的当前投影为 2251 个展示岗位组；其中 305 组含多条记录，合并余量为 749 条。此处“岗位数”默认指组数，不代表已识别出独立招聘岗位或批次，不能按招聘人数加权。来源数仍可作为数据规模说明。

## 2. 薪资

数值使用交接包 `salary_min_monthly`、`salary_max_monthly`，单位人民币元/月；原文 `salary_display` 保留展示。不从原文重解析、不静默改用缓存薪资，也不因数值看起来较高自行裁剪。

参与区间中点统计的岗位组须同时满足：上下限均存在、可解析为有限正数、下限不大于上限，以及组内没有尚未核实的薪资原文倒置记录。中点 `m=(下限+上限)/2` 是岗位区间的估算值，不是实际到手工资、平均员工收入或确认录用薪资。

| 情况 | 处理 |
| --- | --- |
| 有效闭区间，包括上下限相等 | 计算一个中点，每组计一次。 |
| 缺少上限或下限 | 保留岗位及已有值、原文；不补齐，不计算中点。 |
| 非正数、非有限数、数值上下限倒置 | 保留来源并列入核对项，不参与薪资统计。 |
| 原文上下限倒置，数字已经交换 | 仍不参与薪资统计，不能把排序后的数值视为已确认。具体 ID 见准备清单。 |
| 其余与缓存数值不同 | 继续使用交接包数值，满足有效区间条件时参与统计；披露来源差异未经逐条原网页核实，不声称缓存或交接值已经被证明更准确。 |

分组比较使用**有效岗位区间中点的中位数**，偶数个中点取中间两值的算术平均，汇总前不先四舍五入。各项同时展示全部岗位组数与参与薪资计算的有效组数；无有效中点时结果为 `null`，显示“暂无有效薪资样本”，不能显示 0。

省级、岗位类别等薪资排名要求该分项至少有 **5 个有效岗位组**，不是 5 个原始 ID；少于 5 必须标记低样本预警，可展示样本量和分布，但不进入排名。这里的薪资有效样本数记作 `N_salary`，须与下一节技能分母 N 区分。阈值是展示约定，不代表统计显著性。排名按中位数降序，同值按分项标签字典序排列，不暗示微小数值差异有实质意义。未知省级地区不进入地区薪资排名，未分类岗位不进入岗位类别薪资排名，但保留在数量和覆盖分母中。

薪资筛选与统计使用同一组交接数值。当前岗位列表已有薪资范围筛选，只以有效闭区间判断与用户区间是否重叠（端点相等也命中）；缺边界、倒置等统计无效组不匹配该数值筛选，仍可在未施加薪资筛选时查看原文。不按文字和数值混用两套规则。分析端点目前不接收列表专属薪资筛选，见第 5 节。

## 3. 地区、学历与经验

首版地区比较以规范省级地区为主；缺失显示“未注明”，数量分布仍保留。城市当前仅四个直辖市有值，城市字段可辅助筛选、展示，不制作全国城市薪资榜，不补造其他城市。四个省级别名仅在分组后映射。

学历以 `education_requirement` 的要求标签分组，岗位组数与同口径薪资中点分布并列呈现。`education_min_code` 只用于选择学历要求范围，不是可计算均值的教育年数；“本科及以上”不等于实际录用者只有本科学历。“不限”是明确来源值，不能与缺失合并。学历相关薪资差异不能解释为个人提升学历的涨薪幅度。

经验首版仅支持 `experience_status` 的要求分布与原文展示；`experience_min_years` 仅 17 条来源记录有值，不建立年限影响模型，不将未注明经验当作零年经验。`recruitment_headcount` 保留，不求和代替岗位数。

## 4. 技能频次、比例与分析边界

在同一筛选集合 G 中定义，并在结果中说明当前采用的地区、类别、技能等筛选条件：

- `N=|G|`：全部匹配岗位组数，包括无标签组。
- `L`：G 中 `skills` 非空的岗位组数。
- `K(s)`：G 中至少有一次技能名 s 的岗位组数；同组重复关系、多份依据都只计一次。
- **技能标注比例** `K(s)/N`；**技能覆盖率** `L/N`。二者同时显示分子、分母及百分比，不能将分母悄悄改成 L。
- 当前 API 还提供 **已标注样本内部比例** `K(s)/L`，即只在有标签组中该技能出现的比例。它可与 `K(s)/N` 并列展示，但必须明确分母，不能称为全部岗位需求率；同时展示 `L/N`，让读者知道标注覆盖的限制。

| 实际响应字段 | 比例 | 解释 |
| --- | --- | --- |
| `ratio_annotated` | `K(s)/L` | 有技能标签的岗位组内部占比。 |
| `ratio_total` | `K(s)/N` | 全部匹配岗位组的技能标注比例，包括无标签组。 |
| `coverage_ratio` | `L/N` | 当前匹配集合的技能标签覆盖率。 |

例如 N=10、L=4、K(Python)=3：两个技能比例分别为 75% 和 30%，覆盖率为 40%；75% 不能写成全部岗位有该需求。

当 N=0 时，`K/N`、`L/N` 和 `K/L` 均为 `null`，频次为 0，技能列表为空，显示“暂无匹配岗位”；不得出现除零、NaN 或 0% 的伪结论。当 N>0 且 L=0 时，覆盖率为 0%，技能列表为空，显示“当前样本暂无技能标签”，不声称没有技能要求。如果明确展示某个字典技能，其频次为 0、全量标注比例 `K/N=0%`，已标注内部比例 `K/L=null`，仍受未标注限制。

技能并集可能改变标签覆盖率，应使用组级分子、分母重新计算；不能沿用来源记录层的 36.9%。2026-10-20 只读复核的组级快照为 833/2251，约 37.01%，只是覆盖现状，运行时以当前筛选集合重算。

首版岗位技能画像仅表示某类别样本中的现有标签频次与覆盖率，可列出常见标签及对应岗位依据。没有标签不代表不需要技能；24 个标签不等于市场全部能力。当前证据不支持完整能力提取或“最佳学习路线”。

首版不纳入行业分析、全国城市榜、经验年限影响模型、个人学习技能后的涨薪预测、技能因果溢价模型。对学历、岗位类别的薪资比较均使用“要求分布”“招聘薪资差异”等表述，不称为个人能力带来的因果提升。

## 5. 当前实现边界与规范差异（2026-10-20）

上文保留应遵循的分组、查询和解释规则，不以代码已有某一分支为由修改规范。当前只读审查发现：

- [overview.py](../backend/app/api/v1/endpoints/overview.py) 和 [stats.py](../backend/app/api/v1/endpoints/stats.py) 仅向仓库转发类别、省份、学历；[jobs.py](../backend/app/api/v1/endpoints/jobs.py) 另转发关键词、薪资和标签有无条件。公共参数模型虽也声明这些局部条件，分析端点并未用它们过滤。因此三个公共条件可在同范围比较，岗位列表的全部局部条件尚未驱动所有图表，不能宣称全产品已实现同一个完整 G。
- [repository.py](../backend/app/db/repository.py) 第 600—601 行的 MongoDB 列表只对用户指定的单字段排序，没有显式 id 二级键；内存路径第 933—945 行也未显式构造二级键。上文稳定同值排序仍是规范要求，本轮不改查询代码。
- 同文件第 91—105 行使用 Python `statistics.median` 与 `quantiles(method="inclusive")` 计算中位数、P25/P75；MongoDB 提供分组/数组，不能说所有分位数全部在数据库完成。当前输出对统计值保留两位小数；本轮未重跑应用或数据库测试。
- 当前清洗资格分支未显式验证 `isfinite`；[字段字典](data-dictionary.md)记录该输入验证边界。真实 JSON 的有效薪资组为 2,194，整体中点中位数为 12,000 元/月，均来自[只读基准审计](review/2026-10-20_203614_data-stack-evidence.json)，不是完整市场薪资或当前在线 API 结果。
- 页面错误或请求未完成时的默认 0、旧图保留、快速切片响应顺序仍有实现限制，见[项目现状报告](review/2026-10-20_203614_project-review.md)；因此不能把界面所有 0 都解释为成功查询后的统计值。

本轮仅整理文档与披露差异，不视为 API、数据、数据库或前端行为修复授权。
