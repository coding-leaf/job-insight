# JobInsight 字段字典

契约确定于 2026-10-17，状态复核于 2026-10-20。当前已有离线分组/分类处理、MongoDB 与 JSON 查询仓库、FastAPI 接口和 Vue 页面；本文继续定义来源字段及业务含义，实际 API 投影差异见第 5 节。原始交接文件只读，来源快照、SHA-256 和本地输入可用性见[来源与处理状态](data-preparation-checklist.md)。本轮替换前的[原文快照](archive/2026-10-20_203614_data-dictionary.md)和[审查清单](review/2026-10-20_203614_documentation-audit.md)保留历史依据。

## 1. 来源与缺失规则

输入为 UTF-8 BOM CSV：岗位主表 `jobs_clean_final.csv`、技能字典 `skills.csv`、岗位技能关系 `job_skills.csv`。它们来自本仓库父目录的历史 `清洗后数据/` 交接包，并非 Git 自带输入；来源位置与哈希见[来源清单](data-preparation-checklist.md)。按 CSV 解码得到的原始单元格字符串先用于[精确分组](statistical-methodology.md)，然后才转换类型、规范地区。

- 空单元格 `""` 映射为 `null`，不得替换成 0、“不限”或“无要求”；`skills` 无关系映射为 `[]`。
- 原始标题、地点、薪资文字和正文保持来源内容。展示“未注明”“未分类”只是缺失值的显示名称，不写回来源文本。
- 数字按十进制解析，不能直接对 `5.0` 文本做整数字符串转换。人数 `5.0` 可精确转换为整数 5；经验 `8.0` 可转换为数值 8。整数类字段如出现非整数值，不四舍五入，应保留原值并列入待核对项。解析失败不得伪装成正常的空值。
- 日期表示发布日，保持 `YYYY-MM-DD`，不增加推测的采集时间或时区。

## 2. 岗位主表的全部 21 列

“当前非空”是 2026-10-17 的来源记录计数，不代表已经逐条核实，也不是运行时常量。

| 字段 | 业务类型 / 当前非空 | 来源含义、缺失与用途 |
| --- | --- | --- |
| `id` | 字符串 / 3000 | 非空且唯一的来源岗位 ID，原值保留；关联技能与离线复核。分组投影的 `id` 采用组内代表 ID，来源表仍保留所有 ID。 |
| `source_url` | 字符串 / 3000 | 来源详情链接，保留原文，供追溯；组投影采用代表记录链接，其他链接通过 `source_ids` 回查来源。 |
| `published_at` | 日期或 `null` / 3000 | 发布日期，供展示与日期筛选，不作为采集时间。 |
| `title` | 字符串 / 3000 | 原始岗位标题，展示、搜索和分类依据；不能用归类后的名称覆盖。 |
| `company` | 字符串或 `null` / 3000 | 来源企业名称，展示和搜索。 |
| `company_type` | 字符串或 `null` / 850 | 企业性质，辅助展示；不是行业。 |
| `company_size` | 字符串或 `null` / 1493 | 企业规模标签，辅助展示，不取范围中点冒充人数。 |
| `work_location` | 字符串或 `null` / 3000 | 来源工作地点文字，展示与追溯，保留“全国”等值。 |
| `province` | 字符串或 `null` / 2748 | 省级地区，主要地区筛选和分析维度；只做下表明确的名称映射。 |
| `city` | 字符串或 `null` / 646 | 可确认城市，辅助展示和筛选；当前仅四个直辖市，不能按省份猜测城市。 |
| `salary_display` | 字符串或 `null` / 3000 | 来源薪资展示文字，保持原文；不用于重新反解析并覆盖交接数值。 |

| `salary_max_monthly` | 十进制数或 `null` / 2911 | 月薪上限，人民币元/月；缺失时不补成下限，不计算区间中点。 |
| `education_requirement` | 字符串或 `null` / 3000 | 学历要求原标签，展示、按要求标签分组；缺失不等于不限。 |
| `education_min_code` | 整数或 `null` / 3000 | 最低学历筛选编码：0=不限，1=大专及以上，2=本科及以上，3=硕士及以上，4=博士及以上。供学历要求筛选，不计算“平均学历”，0 不是缺失。 |
| `experience_requirement` | 字符串或 `null` / 3000 | 经验要求原文字，辅助展示。 |
| `experience_min_years` | 十进制数或 `null` / 17 | 可确认的最低工作年数；保留供追溯，首版不作为主要筛选和统计维度，缺失不填 0。 |
| `experience_status` | 字符串或 `null` / 3000 | 当前值为“未注明”“应届/校招”“年限要求”；用于要求分布，不据此推算经验年数。 |
| `major_requirement` | 字符串或 `null` / 1609 | 专业要求，详情展示；不代替行业、岗位类别或技能要求。 |

## 3. 技能输入与嵌套投影

技能字典仅有 `skill_name` 一列，当前 24 个唯一名称。关系文件的 `job_id` 关联岗位 `id`，`skill_name` 关联字典，`origin` 与 `evidence` 分别表示来源标记和依据文字。导入前检查关联，不将悬空关系静默丢弃。

业务字段 `skills` 的最小形状如下。示例仅说明格式，不是对某条岗位的分类或补标结果。

```json
[
  {
    "skill_name": "Python",
    "provenance": [
      {"origin": "source_tag", "evidence": "Python"}
    ]
  }
]
```

`skill_name` 是非空字符串；`provenance` 是非空数组，每项保留一对 `origin: string | null`、`evidence: string | null`。先收集组内全部来源记录的关系，再按原始技能名去重；同一技能下按完整 `(origin, evidence)` 对去重，不能只保留第一条依据，也不能将不同来源标记与依据交叉拼配。技能及依据对按原值字典序排列，空值在前，以便重复生成时结果一致。

当前 2880 条关系均为 `origin=source_tag`，`evidence` 仅重复技能名；它不是岗位正文引文，不能声称已经完成正文能力提取。保留现有技能名，不在导入时自行合并同义词。

## 4. 最小业务派生字段

| 字段 | 类型与规则 |
| --- | --- |
| `source_ids` | 非空字符串数组，保留组内全部来源 ID，按原值字典序升序，无重复；`id=source_ids[0]`。原值比较区分大小写，不采用本地化排序。单条记录也保留长度为 1 的数组。 |
| `job_category` | 11 个固定类别之一或 `null`；组级唯一最终值，由[分类契约](job-classification.md)计算，不能直接取代表记录的类别。 |
| `category_source` | `rule`、`reviewed` 或 `null`；表示组级最终类别依据。已确认无法分类时为 `reviewed` 且类别为 `null`；无依据或待解冲突时两者均为 `null`。 |
| `skills` | 上节技能数组；由全组关系并集构造，无技能关系为 `[]`。 |

复核 CSV 是离线处理记录，字段及状态以[岗位分类说明](job-classification.md)为准，不自动成为产品页面字段。区间中点的业务定义见[统计口径](statistical-methodology.md)；当前实现选择将中点及资格标记保存于组级投影，见下一节。

## 5. 当前投影与 API 类型边界（2026-10-20）

[clean_and_group.py](../temp/data_prep/clean_and_group.py) 第 251—290 行在上述来源及组级字段外生成四项薪资派生字段；当前本地 JSON 共 29 个顶层字段。它们是现有实现，不替代来源上下限与原文。

| 实际派生字段 | 类型与当前含义 |
| --- | --- |
| `salary_eligible_for_midpoint` | 布尔值，是否参与区间中点统计；业务资格仍应满足统计契约的有限正数、有效闭区间及原文倒置排除条件。 |
| `salary_midpoint` | 数值或 `null`，符合资格时为区间中点，非实际收入。 |
| `salary_stat_excluded` | 布尔值，当前实现标识已知原文倒置或数值异常；缺上/下限时可以为 false，因此不能把 false 等同于有资格。资格以 `salary_eligible_for_midpoint` 为准。 |
| `salary_exclude_reason` | 字符串或 `null`，保留原文倒置、缺少边界等排除说明。 |

[backend/app/schemas/job.py](../backend/app/schemas/job.py) 的 API `JobItem` 复用这些字段，但与来源业务契约仍有差异：来源允许 `company=null`、十进制薪资、`origin/evidence=null`，API 当前分别要求公司为字符串、薪资边界为整数、依据字段为字符串。不能将“字段同名”表述为所有输入类型均已 1:1 对齐；本次未变更这些类型，也未证明当前样本已因此失败。

规范还要求薪资为有限正数；当前清洗资格分支未显式检查 `isfinite`。这是输入验证的待核对项，不应通过删掉有限性要求掩盖，也不能据此断言现有基准含异常值。当前数据规模与覆盖见[只读审计证据](review/2026-10-20_203614_data-stack-evidence.json)，不写入运行时常量。
